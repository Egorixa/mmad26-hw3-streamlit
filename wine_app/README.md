# Подборка хороших вин

Приложение к ДЗ-3. Логистическая регрессия по лабораторному анализу предсказывает, хорошее ли вино. Модель обучена в ноутбуке `Курюкин246_HW3_MMDA.ipynb`, в приложении она только загружается.

## Запуск

Python 3.12 (проверено на 3.12.12). Модель сохранена в `scikit-learn` 1.8.0, поэтому версии из `requirements.txt` лучше не менять.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Если команды `python3.12` нет, можно создать `.venv` из любого Python 3.12 по полному пути, например из conda: `/путь/к/conda/bin/python -m venv .venv`. Или поставить его через `brew install python@3.12`.

Для Streamlit Community Cloud: файл `wine_app/app.py`, Python 3.12 в Advanced settings.

## Что внутри

- `app.py` – само приложение
- `model.joblib` – пайплайн `StandardScaler` + `LogisticRegression`, обученный на train
- `config.json` – порог по умолчанию, подобранный на валидации
- `test.csv` – тестовая выборка, по ней считаются метрики и диапазоны полей ввода
- `requirements.txt` – версии библиотек

В приложении четыре вкладки: оценка одного вина, метрики на тесте при текущем пороге (матрица ошибок, precision, recall, F1, ROC- и PR-кривые), пакетное предсказание по CSV с возможностью скачать результат и коэффициенты модели. Порог задаётся слайдером в боковой панели и действует на всех вкладках.

## Кэширование (задание 4.5)

Модель загружается через `st.cache_resource`, потому что это один объект, который только читается: его достаточно загрузить один раз на весь сервер и не копировать. Таблицы и вероятности на тесте кэшируются через `st.cache_data`. Он хранит данные в сериализованном виде и каждому вызову отдаёт свою копию, так что если в одной сессии таблицу случайно изменят, в других она останется прежней.

Без декоратора `joblib.load` вызывался бы при каждом действии пользователя, ведь Streamlit перезапускает `app.py` целиком, например при каждом движении слайдера. Модель читалась бы с диска заново, а вероятности на тесте пересчитывались бы, хотя от порога они не зависят. Результат был бы тот же, но приложение работало бы медленнее.
